# Event food order

## When to use
Event food should be picked up fresh or delivered mid-event (or just before). Keep this **separate** from the Amazon supplies cart.

**Vendor = wherever the user wants.** Ask which restaurant, chain, or app (DoorDash, Uber Eats, campus catering, local spot, etc.). Do **not** default to In-N-Out or any specific brand unless the user names it.

## Sizing (required before ordering)
1. **Headcount + buffer:** Size from expected attendees plus **~10% buffer** (round up). Show the math: `headcount → buffered count → items/qty`.
2. **Dietary split:** Ask for and reflect dietary needs (vegetarian, vegan, gluten-free, halal, allergies, etc.). Split the order into labeled sections or line items — do not bury dietary flags in a single lump order.
3. **Cost estimate:** Produce a **total cost estimate** (items + tax + tip + delivery fees) and show it to the user **before** any real payment. If the estimate exceeds budget, flag it and propose cuts before placing the order.

## Plan to produce
1. **Vendor + method** — restaurant/app, pickup vs delivery, nearest location or delivery address.
2. **Timing** — order/pickup ~60–75 minutes after doors (or 45 minutes before you want food in-room); adjust for delivery ETA.
3. **Envoys** — 1–2 people with transport (pickup) or point person for delivery handoff; phones on the sheet.
4. **Menu pack** — sensible default order for buffered headcount based on the vendor's menu, with dietary sections.
5. **Custom order sheet** — columns: name, item + mods, dietary flags, paid?
6. **Logistics blanks** — location/address, parking or drop-off instructions, target back-in-room time.
7. **Reimbursement** — photo receipt; club Venmo/card rules.

## Execution
1. Confirm vendor, headcount, budget, and dietary needs with the user.
2. Compute buffered quantities and dietary split; produce the order plan (markdown or CSV) the organizer can print or share in the club chat.
3. Present the **cost estimate** and get approval before payment.
4. Include a short call-ahead or in-app order script when useful.
5. **Stop before placing a real paid order** unless the user explicitly approves payment.
6. On approval: place order via the chosen app/site or coordinate call-ahead pickup; track ETA; confirm handoff back in-room.

## Guardrails
- Do not place a real paid order in demo/dry-run mode.
- Do not default to any specific restaurant — always ask.
- Do not charge or submit payment without showing the cost estimate first.
- Collect orders (+ payment method) before the run when possible.
- Keep food staging away from laptops / drink stations.
- Separate from Amazon supplies — never mix food into the supplies cart.

## Deliverable
A markdown or CSV order plan the organizer can print or share in the club chat, plus a short call-ahead or order script. Report vendor chosen, headcount math, dietary split, cost estimate, timing, envoys, and payment status.
