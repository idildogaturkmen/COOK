# Luma event invite

## When to use
After the event concept is roughly set (name, date/time, capacity). Prefer **one platform per event** — if the club already chose Partiful, do not also create Luma unless asked.

## Creative inputs (required before drafting)
Do **not** start writing copy or opening Luma until these are collected:

### Vibes
- Mood / energy (e.g. cozy build night, hype demo day, chill cafe hang)
- Visual references if any (colors, textures, campus inside jokes)
- What guests should *feel* when they land on the page

### Brand assets
- Club logo (file or link) if available
- Club colors / fonts / wordmark rules
- Existing event graphics or past Luma covers to match
- If none exist, note "no assets" and describe a cover direction instead

### Language
- Register: casual campus / professional / bilingual / etc.
- Words to use or avoid (club name spelling, inside jokes, accessibility language)
- Tone guardrails (fun, not corporate; beginners welcome, etc.)

Confirm dry-run mode up front: if yes → fill the form and **stop before Publish**.

## Also confirm
- Event title (working title OK — refine with vibes)
- Date + start/end time (timezone = user's local / campus)
- Location (or "TBD — campus room")
- Capacity / guest limit
- Visibility: public / unlisted / approval-required (default: unlisted or approval for club demos)

## How to use vibes + assets + language
- **Title** — short, energetic; reflect vibes; use club naming rules from Language.
- **Description** — lead with what people will *do* and *feel* (from Vibes); skimmable (short paragraphs or 3–5 bullets); mention food/theme hooks in one line when relevant; beginners-welcome line for build/workshop nights; honor Language register and avoid-list.
- **Cover** — use Brand assets (logo, colors) when provided; otherwise generate or select imagery that matches Vibes; never use off-brand stock that clashes with club colors.
- **Consistency** — title, description, and cover should feel like one package; if assets are missing, say so in the draft note to the user.

## Browser process (box browser)
1. Open https://lu.ma (or https://luma.com — use whatever the live product redirects to).
2. If login/SSO/2FA is required, hand the user the box; never ask for their password.
3. Start **Create event** (or open an existing draft if continuing).
4. Fill: title, date/time, location, capacity, description/blurb, cover — all aligned to the creative inputs above.
5. Screenshot the draft preview / form and show the user.
6. **Stop.** Ask for explicit publish approval.
7. Only on "publish yes": click Publish / Go live, then report the public Luma URL.
8. Optional follow-up: copy link into calendar, Slack, or email **only if asked**.

## Guardrails
- Never publish without an explicit yes in chat.
- Never buy paid Luma boosts / paid features without approval.
- Demo/dry-run mode: leave as draft or clearly labeled test; do not spam the club list.
- If Luma UI changed, adapt to current labels; don't invent clicks you can't see.
- Prefer the signed-in browser over nonexistent Luma connectors.
- Do not draft title, description, or cover until Vibes, Brand assets, and Language are collected (or explicitly waived by the user).

## Report back
- Vibes, brand assets, and language used (or waived)
- Draft fields filled
- Screenshot of the draft
- Publish status (draft vs live)
- Event URL if live
