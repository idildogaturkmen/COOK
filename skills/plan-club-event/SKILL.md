# Plan club event

> **DEMO / dry-run:** Never publish invites or place paid orders without explicit user approval. Build plans and carts only until the user says go.

## Audience
Busy college club officers (social chairs, presidents, treasurers). Thin budgets, campus rooms, volunteer labor.

## Loop
1. **Intake** — vibe, date window, guest count, budget, campus/city, **event ZIP** (for delivery lead times), dietary needs, must-haves, and **Luma creative inputs** (vibes, brand assets, language — collect early even if the invite comes later).
2. **Concept** — propose 1–2 tight concepts + short run-of-show (not a novel). Prefer fun, hostable themes (e.g. DIY matcha cafe + build night) over generic "mixer".
3. **Supply note** — flag the **Amazon vs local** split upfront: durables/shelf-stable on Amazon; refrigerated items (milk, ice) via Instacart or campus store.
4. **Invite draft** — use collected **vibes**, **brand assets**, and **language** before copy; write Luma or Partiful title/blurb/cover aligned to those inputs. Prefer one platform per event. Show draft; **never publish** without explicit yes.
5. **Lock gate** — only after the user greenlights final date, headcount, budget, and **ZIP**, move to supplies/food ordering skills.
6. **Day-of brief** — checklist: arrivals, human tasks, guest snapshot, who owes what.

## Guardrails
- Never publish an invite or place a paid order without explicit approval.
- Always show a cost estimate before any cart/checkout work.
- If Google Workspace blocks OAuth connectors, use the signed-in browser instead.
- Keep tone warm, sharp, campus-fluent; short messages.

## Handoffs
- Create the Luma page (vibes + brand assets + language collected first) → skill `Luma event invite`
- Cafe/party supplies (headcount math, tiered ratings, Amazon vs local split) → skill `Amazon event supplies`
- Food from any restaurant/app (headcount + ~10% buffer, dietary split, cost estimate) → skill `Event food order`
